# Support and Incident Process

## Support-Eingang

- Ein zentraler Support-Kanal genügt für den ersten Betrieb.
- Jede Meldung bekommt eine verantwortliche Person.

## Priorisierung

- `P0`: Login, Datenverlust, komplette Nichtverfügbarkeit, schwere Datenschutzverletzung
- `P1`: Kernflow gestört, aber Workaround vorhanden
- `P2`: UX-/Darstellungsfehler ohne akute Blockade

## Standardprozess

1. Meldung aufnehmen.
2. Kategorie markieren: Auth, Bonsai, Reminder, Upload, Community, Datenschutz.
3. Schweregrad setzen.
4. Reproduktion versuchen.
5. Entscheidung: sofortiger Fix, geplanter Fix oder bewusste Produkteinschränkung.

## Community-spezifische Fälle

- Privacy-Beschwerde
- Unerwünschter Inhalt
- Falsch sichtbare Profilinformationen
- Problematische Bilder oder Kommentare

## Sofortmaßnahmen bei Community-Fällen

1. Betroffenen Inhalt identifizieren.
2. Risiko einschätzen.
3. Falls nötig Inhalt temporär ausblenden oder entfernen.
4. Entscheidung intern dokumentieren.

## Incident-Abschluss

- Ursache notieren
- Auswirkung notieren
- Getroffene Maßnahme notieren
- Nächste Präventionsmaßnahme festhalten
