# Versioned care plan rules

Care plan rules start as editorial product data versioned with the application code, not as user-editable data or an admin-managed database table. The initial species catalog covers Ficus, Chinese elm, Japanese maple, juniper, pine, azalea, privet, hornbeam, beech, and serissa rather than botanical completeness. The existing free-text species field remains separate from the curated species selection; only the curated selection can produce a care-plan preview or activation, and the app does not infer a care-plan species from matching text. Existing bonsais are not migrated or auto-activated; users can select a curated species later and explicitly activate the care plan from the bonsai context. Activation generates system reminders for a rolling 12-month period from the activation date, not for a fixed calendar year. Rules use month windows that the app turns into concrete reminder dates on the first day of each applicable month; a rule may be general or constrained by the bonsai's existing indoor/outdoor classification, and bonsais without that value are treated as outdoor for care-plan purposes. The first release deliberately excludes watering reminders, weather, location, regional climate zones, or complex weekday/week-number logic, and the UI labels care-plan dates as typical timing rather than guaranteed advice. Watering stays out of system-generated care plans because it depends heavily on substrate, placement, and current conditions. This keeps the first paywalled care-plan release reviewable, testable, and small while the product value is still being validated; rule changes require a deployment until there is a clear need for operational editing.
