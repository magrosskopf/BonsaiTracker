# Stripe-backed care plan entitlement

The first paywalled care-plan feature includes Stripe integration rather than a placeholder-only paywall, because the feature is intended to validate paid product behavior end to end. The commercial product is the single annual "Bonsai Tracker Plus" subscription for 19,99 EUR, with no monthly plan, one-time purchases, tiers, or trial logic. Bonsai Tracker Plus currently contains the care plan and can later contain additional product benefits; it is not synonymous with the care plan itself. Care-plan previews are visible before payment as a 12-month list of planned reminders; activation and system-reminder generation require entitlement. Users reach Stripe Checkout either from the contextual care-plan paywall for a specific bonsai or from the profile as a product-level upsell. Checkout return URLs are navigation only: the UI confirms a completed Checkout only after the server retrieves the Stripe Checkout Session and verifies that it belongs to the signed-in user, while care-plan activation remains allowed only after the independent server-side entitlement reflects Stripe subscription state. Payment grants access but does not modify a bonsai; system reminders are created only when the user explicitly activates a care plan for that bonsai. The first UI scope is bonsai creation, bonsai detail, reminders, and profile; there is no standalone pricing page. Inactive users can start Checkout from the profile without selecting a bonsai; after a verified return, the profile points them to bonsai selection as the next step. Active users reach Stripe Customer Portal there for cancellation and payment-method management. A user may have at most one open Plus Checkout Session or non-terminal Plus subscription: `active`, `trialing`, `incomplete`, `past_due`, `unpaid`, and `paused` block another purchase, while the terminal states `canceled` and `incomplete_expired` permit a new Checkout. The application checks that internal entitlement for care-plan activation and reminder generation; Stripe is the payment source that creates or removes that entitlement, not the domain concept used throughout feature code. Stripe subscription statuses `active` and `trialing` grant the entitlement; `past_due`, `unpaid`, `canceled`, `incomplete`, `incomplete_expired`, and `paused` do not. When the entitlement ends, users cannot activate or resynchronize care plans, but already generated system reminders remain visible and actionable.
