# Grilling Skill

**Status**: IMPLEMENTED  
**Created**: 2026-07-03  
**Last Modified**: 2026-07-03

## Purpose/Goal

Create a personal Codex skill named `grilling` that makes Codex relentlessly interrogate a user's plan or design before implementation. The skill should force clarification of assumptions, dependencies, risks, and decision branches until Codex and the user reach a shared understanding.

## Functional Requirements

1. The skill must be named `grilling`.
2. The skill must trigger when the user wants to stress-test a plan or design before building.
3. The skill must also trigger when the user uses "grill" trigger phrases.
4. The skill must instruct Codex to interview the user relentlessly about every aspect of a plan.
5. The skill must instruct Codex to walk down each branch of the design tree and resolve dependencies between decisions one-by-one.
6. The skill must require Codex to ask exactly one question at a time.
7. The skill must require Codex to wait for feedback on each question before continuing.
8. The skill must require Codex to provide a recommended answer for each question.
9. The skill must instruct Codex to inspect the codebase instead of asking the user when a question can be answered by local exploration.
10. The skill must prevent Codex from enacting the plan until the user confirms shared understanding has been reached.
11. The skill must be installed in a location where Codex can discover it automatically unless the user specifies another location.

## Technical Constraints

- Create a Codex skill folder using the system `skill-creator` process.
- Use lowercase skill naming rules; the folder name must match `grilling`.
- The skill must contain a valid `SKILL.md` with YAML frontmatter containing only `name` and `description`.
- Include `agents/openai.yaml` metadata generated by the skill creation tooling.
- Do not add unrelated README, changelog, installation guide, or auxiliary documentation.
- Default creation location is `${CODEX_HOME:-$HOME/.codex}/skills`.
- Do not modify the central `workflows/` directory.
